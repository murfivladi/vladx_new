# VladX — спецификация языка v0.1

Статус: соответствует реализации в этом репозитории (`cargo test` и `scripts/test-all.sh` проверяют утверждения этого документа). Схема AST — `spec/ast.schema.json`, словарь — `spec/keywords.toml`. Исходное техническое задание — `docs/HANDOVER.md`.

## 1. Принципы

1. Код читается как фраза на живом языке. Ключевые слова — **только** `ru`, `it`, `scn`; английских ключевых слов нет.
2. Слова — данные, не код: все словоформы живут в `spec/keywords.toml`. Парсер работает с нейтральными id операций.
3. Один смысл — один AST: код на трёх языках даёт одинаковый JSON (без `span` и поля `lang` корня).
4. Порядок слов фиксирован. Парсер не угадывает перестановку, а объясняет канон (`E-ORDER-*`).
5. Ошибка учит: позиция, стабильный код латиницей, сообщение и подсказка.
6. Лимиты исполнения действуют всегда.
7. Внешний мир (файлы, сеть) по умолчанию открыт, как в Node; сузить можно явно.

## 2. Лексика

- Исходник — UTF-8 (`E-ENC-001`), BOM игнорируется, текст нормализуется в NFC.
- Ключевые слова сравниваются без учёта регистра (`Скажи` = `скажи`). Имена — с учётом регистра.
- Фразы из нескольких слов (`для каждого`, `больше или равно`, `и сохрани в`) распознаются целиком; из подходящих выбирается самая длинная. Слова фразы должны стоять на одной строке.
- Имя: буквы любого алфавита, цифры, `_`; не начинается с цифры; не совпадает с ключевым словом (`E-IDENT-002`). Слово сразу после точки — всегда имя свойства (`liste.возьми` допустимо, хотя «возьми» — служебное слово импорта).
- Число — только float64: `5`, `3.7`. Печатается без лишнего `.0`: `5`, `2.5`. Слитное «число+буквы» — `E-LEX-002`.
- Строка — только в двойных кавычках, на одной строке (`E-LEX-001`). Экранирование: `\n \t \r \" \\ \{ \}`.
- Интерполяция `{имя}` или `{путь.по.полям}`. Внутри скобок выражение запрещено (`E-STRING-003`, подсказка «вынесите в переменную»), пустые скобки — `E-STRING-002`, незакрытые — `E-STRING-001`. `\{` — литеральная скобка. Первым сегментом может быть `это`/`questo`/`chistu`.
- Комментарии: `//` и `#` до конца строки. `/* */` нет.
- Символы: `{ } ( ) [ ] , : . ; = + - * / %`. Остальное — `E-LEX-003`; для `> < == != ! && ||` подсказка показывает слово-замену.
- Отступы не значимы. Точка с запятой необязательна. Две инструкции в одной строке без `;` — `E-SYNTAX-016`.
- Бинарный оператор и `(` вызова должны стоять на той же строке, что и левый операнд (иначе это новая инструкция). Перенос строки допускается после оператора и внутри `[...]`, `{...}`, `(...)` между элементами.

## 3. Словарь

21 операция `[[op]]` + 12 слов выражений `[[word]]` (литералы, сравнения, логика) + имена типов `[[type]]`. Полный список — `vladx keywords` или сам `keywords.toml`. Канон `ru`:

| id | ru | служебные слова |
|---|---|---|
| `var.declare` | пусть, создай, заведи, объяви | `be`: будет (или `=` во всех языках) |
| `var.mutable` | изменяй, изменяемая, переменная | значение после `станет` или `=` |
| `var.assign` | станет, присвой, замени на | — |
| `io.say` | скажи, выведи, напиши, покажи | — |
| `io.ask` | спроси | `into`: и сохрани в, и запиши в |
| `ctrl.if` / `ctrl.else` | если / иначе, в противном случае | `then`: то (необязательно) |
| `ctrl.while` | пока, до тех пор пока | — |
| `ctrl.repeat` | повторяй | `times`: раз |
| `ctrl.foreach` | для каждого | `iter`: из, в |
| `ctrl.iterate` | пройди по | открытый вопрос §11: даёт `E-SYNTAX-001` с подсказкой «для каждого» |
| `ctrl.break` / `ctrl.continue` | прерви, останови / продолжи, пропусти | — |
| `fn.declare` / `fn.return` / `fn.self` | функция / верни, возвращает / это | — |
| `obj.withProto` | создай объект с прототипом, с прототипом | — |
| `err.try` / `err.catch` / `err.throw` | попробуй / поймай, при ошибке / брось, вызови ошибку | — |
| `mod.import` | импортируй, подключи | `from`: из; `take`: возьми |

Литералы: `ничего`/`пусто`, `истина`/`правда`/`да`, `ложь`/`неправда`/`нет`. Сравнения: `больше`, `меньше`, `равно`/`равен`, `не равно`, `больше или равно`, `меньше или равно`. Логика: `и`, `или`, `не`.

Добавление операции: (1) `[[op]]` в `keywords.toml`; (2) `cargo run -p xtask`; (3) разбор в `parser.rs` по id; (4) исполнение в `vladx-runtime`; (5) тест в `crates/vladx-runtime/tests/exec.rs` и пример в `examples/`.

## 4. Грамматика (EBNF, слова — канон `ru`)

```ebnf
программа    := инструкция*
блок         := "{" инструкция* "}"
инструкция   := объявление | присваивание | вывод | ввод | условие | цикл
              | функция | возврат | "прерви" | "продолжи" | попытка | бросок
              | импорт | выражение

объявление   := "пусть" имя ("будет" | "=") выражение
              | "изменяй" имя ("станет" | "=") выражение
присваивание := цель "станет" выражение            (* цель: имя или поле a.b *)
вывод        := "скажи" выражение
ввод         := "спроси" выражение "и сохрани в" имя

условие      := "если" выражение "то"? блок ("иначе" (блок | условие))?
цикл         := "пока" выражение блок
              | "повторяй" выражение "раз" блок
              | "для каждого" имя "из" выражение блок

функция      := "функция" имя "(" параметры? ")" блок
параметр     := имя (":" имяТипа)? ("=" выражение)?
возврат      := "верни" выражение?                 (* выражение — на той же строке *)

попытка      := "попробуй" блок "поймай" имя блок
бросок       := "брось" выражение
импорт       := "импортируй" имя
              | "импортируй"? "из" строка "возьми" имя ("," имя)*

выражение    := или
или          := и ("или" и)*
и            := сравнение ("и" сравнение)*
сравнение    := сумма (опСравнения сумма)?        (* не цепляется: a < b < c — ошибка *)
сумма        := произведение (("+" | "-") произведение)*
произведение := унарное (("*" | "/" | "%") унарное)*
унарное      := ("-" | "не") унарное | постфикс
постфикс     := первичное ("(" аргументы? ")" | "." имяСвойства)*
аргумент     := (имя "=")? выражение               (* именованные — после позиционных *)
первичное    := число | строка | список | словарь | "ничего" | "истина" | "ложь"
              | "это" | имя | "(" выражение ")"
              | "функция" "(" параметры? ")" блок
              | "создай объект с прототипом" постфикс "{" поля? "}"
список       := "[" (выражение ("," выражение)* ","?)? "]"
словарь      := "{" (ключ ":" выражение ("," ключ ":" выражение)* ","?)? "}"
ключ         := имя | строка
```

Значение после ключевого слова (`скажи`, `пусть x будет`, `если`, `пока`, ...) должно начинаться на той же строке (`E-SYNTAX-011`).

## 5. Семантика

### 5.1 Значения

`ничего` · логическое · число (f64) · строка · список · словарь/объект (словарь с необязательным прототипом) · функция (замыкание или встроенная) · модуль · ошибка (пойманная ошибка исполнения: поля `код`, `сообщение`).

Ложны: `ничего`, `ложь`, `0`, NaN, `""`. Всё остальное истинно.

### 5.2 Имена и изменяемость

- Блочный скоуп: каждый `{ }` — новый скоуп; тело цикла — новый скоуп на каждой итерации.
- `пусть` — неизменяемая привязка; повторное объявление в том же блоке — `E-NAME-001`; присвоение — `E-NAME-002`. Затенение во вложенном блоке разрешено.
- `изменяй` — изменяемая привязка, меняется словом `станет`.
- Содержимое списков и словарей изменяемо всегда.
- Объявления функций поднимаются: функцию можно вызвать выше её объявления. Из тела функции можно ссылаться на имена, объявленные в объемлющем блоке позже.
- `спроси … и сохрани в имя` присваивает существующей изменяемой переменной или объявляет новую изменяемую.
- Необъявленное имя — `E-NAME-004` ещё до запуска; подсказка предлагает похожее имя (`lista` → `liste`).

### 5.3 Приведение типов (операция выполняется, печатается предупреждение)

| Выражение | Результат | Предупреждение |
|---|---|---|
| `"5" + 3` | `"53"` | `W-COERCE-001` |
| `5 + "3"` | `"53"` | `W-COERCE-001` |
| `"5" * 2` | `10` | `W-COERCE-002` |
| `ничего + 1` | `1` | `W-COERCE-003` |
| `истина + 1` | `2` | — |
| `ничего равно ничего` | `истина` | — |
| `0 равно "0"` | `истина` | `W-COERCE-004` |

Строка, которую нельзя прочитать как число, в арифметике — `E-TYPE-005`. `список + список` — новый склеенный список. `равно` сравнивает списки и словари по содержимому. `больше/меньше` — числа и строки (строки лексикографически); строка с числом — через приведение (`W-COERCE-004`). Деление и остаток на 0 — `E-MATH-001/002`. Одно предупреждение печатается один раз на место в коде.

### 5.4 Функции и объекты

- Функции первого класса; замыкания захватывают окружение по ссылке.
- Аргументы позиционные и именованные. Лишние — `E-ARGS-001`, недостающие — `E-ARGS-002` (до исполнения тела). Встроенные функции именованных не принимают (`E-ARGS-003`).
- Значения по умолчанию вычисляются при каждом вызове и видят предыдущие параметры.
- Подсказка типа `a: число` проверяется при вызове (`E-TYPE-002`). В AST хранится нейтральный id: `number`, `string`, `bool`, `list`, `map`, `function`.
- Нет `верни` — результат `ничего`.
- Метод — функция в поле объекта; при вызове `объект.метод()` слово `это` указывает на объект. Вложенная лямбда видит `это` лексически.
- `создай объект с прототипом П { поля }`: свойство ищется в своих полях, затем по цепочке прототипов. Отсутствующее поле — `ничего`; вызов отсутствующего метода — `E-PROP-001`; поле у `ничего` — `E-NULL-001`.

### 5.5 Ошибки

- `брось значение` бросает любое значение; `попробуй { } поймай е { }` ловит его как есть.
- Ошибки исполнения (кроме лимитов `E-LIMIT-*`) тоже ловятся: `е` — значение-ошибка с полями `е.код` и `е.сообщение`.
- Ожидаемые сбои платформы (файлы, сеть, JSON) приходят как такие ошибки с кодами `E-FILE-*`, `E-NET-001`, `E-JSON-001`.
- Непойманное исключение — `E-UNCAUGHT`, программа останавливается; уже напечатанный вывод сохраняется.

### 5.6 Лимиты

| Лимит | По умолчанию | Код |
|---|---|---|
| шаги (инструкции, итерации, вызовы) | 10 000 000; в браузере 3 000 000 | `E-LIMIT-001` |
| глубина рекурсии | 1 000 | `E-LIMIT-002` |
| время (CLI) | 10 с, `--max-seconds 0` — без лимита | `E-LIMIT-003` (мягкая остановка) |

## 6. Стандартная библиотека

Модули — значения в глобальном скоупе (`импортируй` проверяет, что модуль есть, и больше ничего не делает).

| Модуль | Функции |
|---|---|
| `numeri` | `корень(x)` (`E-MATH-003` для x<0), `модуль(x)`, `округли(x, знаков?)`, `пол(x)`, `потолок(x)`, `случайное()` / `случайное(от, до)` |
| `testo` | `длина`, `верхний`, `нижний`, `обрежь`, `раздели(s, разд=" ")` (`""` — по символам), `соедини(список, разд="")`, `содержит`, `начинается`, `заканчивается`, `замени(s, что, на)` (все вхождения), `кусок(s, от, до?)` (в символах, `до` не включается), `символ(s, i)`, `повтори(s, n)`, `слова(s)` |
| `liste` | `добавь(л, x)` (меняет список, возвращает его), `размер`, `возьми(л, i)` (`E-INDEX-001`), `сортировка` (копия), `переверни` (копия), `содержит`, `найди` (индекс или -1), `кусок(л, от, до?)` (`до` не включается), `соедини(л, разд)` → строка / `соедини(а, б)` → список, `выбери` (случайный элемент) |
| `mappe` | `ключи`, `значения`, `есть(м, ключ)`, `размер`, `удали(м, ключ)` → логическое |
| `caso` | `дробь()` ∈ [0,1), `целое(от, до)` включительно (`E-VALUE-002`), `выбери(список)`, `перемешай(список)` (копия) |
| `tempo` | `сейчас()` → `ЧЧ:ММ:СС` местного времени хоста, `миллисекунды()`, `часы(секунды)` (`3661` → `01:01:01`) |
| `json` | `запиши(значение)` → компактная строка (порядок полей сохраняется), `прочитай(строка)` (`E-JSON-001`) |
| `file` | `прочитай(путь)`, `запиши(путь, данные)` (создаёт папки), `есть(путь)`, `список()` (относительные пути, `папка/файл.txt`, по алфавиту), `удали(путь)` |
| `rete` | `получи(url)` → тело строкой, `получиJson(url)` → значение, `разрешено()` → разрешена ли сеть |

Глобальные функции: `длина(x)`, `размер(x)` (строка, список, словарь), `строка(x)`, `число(x)` (`E-TYPE-001`).
Индексы везде с 0. Адрес для `rete` обязан начинаться с `http://` или `https://` (`E-NET-001`).

## 7. Хост, файлы и сеть

Ядро общается с миром только через трейт `Host`: `read`, `write`, `delete`, `list`, `get` (+ служебные `ask_permission`, `input`, `now_ms`, `say`, `warn`, `should_stop`).

**Разрешения по умолчанию открыты.** Если доступ сужен (`--no-files`, `--no-net`, снятая галочка), при первой попытке ядро один раз спрашивает человека (`ask_permission`). Согласие — программа продолжается; отказ — `E-FILE-001`/`E-NET-001` с текстом «нужно разрешение человека на доступ к …».

| | CLI | Площадка с сервером (shared-хостинг или `vladx serve`) — «как Node» | Площадка без сервера |
|---|---|---|---|
| файлы | настоящий диск; относительные пути — от папки программы; абсолютные и `..` работают; `--restrict-files` — только папка программы; `список()` рекурсивен и пропускает `target`, `.git`, `node_modules` | пишутся **сразу**, в момент вызова: `vladx-fs.php` (рабочая папка на браузер, квоты) или диск у `vladx serve --files` | хранилище браузера (OPFS); запись — после завершения программы |
| сеть | HTTPS (ureq + rustls), таймаут 20 с, `User-Agent: vladx/0.1`, прокси окружения (с учётом `NO_PROXY`) | через `vladx-fetch.php` / `vladx serve`: любые сайты, без CORS; внутренняя сеть сервера запрещена | синхронный XHR: только сайты с CORS |
| вывод | сразу | сразу (импорт `vx_host_say`) | сразу |
| `спроси` | stdin | программа **ждёт** ответа: страница изолирована (COOP/COEP от `index.php` или `vladx serve`), worker стоит на `Atomics.wait` | программа останавливается и запускается заново с ответами (время, случайности, сеть в сеансе те же) |
| время | живое | живое | зафиксировано на сеанс |
| спросить человека о доступе | отказ с объяснением | панель «Разрешить и запустить» | то же |

Протокол сервера (одинаков у PHP и `vladx serve`): `vladx-fs.php` — `POST {op: list|read|write|delete|stat, path, data}` с заголовком `X-VladX-Workspace`; `vladx-fetch.php?url=…` — тело ответа сайта (ошибка посредника — заголовок `X-VladX-Error`); `vladx-llm.php` — §11. `GET` без параметров у каждого отвечает `{"available": …}` — по нему площадка находит сервер рядом с собой.

## 8. Нейтральный AST

JSON по `spec/ast.schema.json` (draft 2020-12, `schema_version = 1`). Дискриминатор — `kind`. Позиции `span` необязательны. `StringLit.parts` — единственный источник истины для интерполяции (`null`, если её нет); `value` хранит исходный текст строки.

```json
{ "kind": "Program", "schema_version": 1, "lang": "ru", "body": [
  { "kind": "Declare", "span": {"line":1,"col":1,"len":5}, "name": "имя", "mutable": false,
    "value": { "kind": "StringLit", "span": {"line":1,"col":17,"len":5}, "value": "мир", "parts": null } } ] }
```

Операторы в `Binary.op`: `add sub mul div mod gt lt ge le eq ne and or`; в `Unary.op`: `neg not`.

## 9. Диагностика

Формат CLI:

```
файл:строка:колонка  КОД  сообщение
  N | строка исходника
    | ^^^^^^^^^
  подсказка: что написать вместо
```

Коды стабильны, латиницей. Используемые в v0.1:

- лексика и кодировка: `E-LEX-001..003`, `E-ENC-001`, `E-DICT-001`;
- порядок слов: `E-ORDER-001, 002, 004..009`;
- синтаксис: `E-SYNTAX-001..016`; строки: `E-STRING-001..003`; имена-ключевые слова: `E-IDENT-002`;
- имена: `E-NAME-001..005`; управление: `E-CTRL-001..003`;
- типы и аргументы: `E-TYPE-001..006`, `E-ARGS-001..003`, `E-PROP-001`, `E-NULL-001`, `E-INDEX-001`, `E-VALUE-001..002`, `E-MATH-001..003`;
- модули и платформа: `E-MODULE-001..002`, `E-FILE-001..003`, `E-NET-001`, `E-JSON-001`;
- лимиты и прочее: `E-LIMIT-001..003`, `E-UNCAUGHT`;
- AST не из парсера: `E-AST-001` (схема), `E-AST-002` (не записывается текстом), `E-AST-003` (неоднозначен после печати и разбора);
- `.vlhmn`: `E-HMN-001` (ИИ недоступен: ключ, сеть, баланс), `E-HMN-002` (ответ не JSON), `E-HMN-003` (некорректно и после повтора), `E-HMN-004` (низкая уверенность); форматтер: `E-FMT-001`;
- предупреждения: `W-COERCE-001..004`.

## 10. WebAssembly ABI

Сборка: `cargo build -p vladx-wasm --target wasm32-unknown-unknown --release`, без wasm-bindgen; стек 32 МБ (`.cargo/config.toml`).

Для редактора площадки: `vx_tokens(src, len, lang)` — разметка для подсветки синтаксиса тем же лексером (`{"t": [[строка, колонка, длина, вид]…], "e": ошибка}`), `vx_check(src, len, lang)` — живая проверка без запуска, `vx_set_interactive(режим)` — «спроси»: 2 — ждать ответа через импорт `vx_host_input` (изолированная страница, как в Node), 1 — без готового ответа программа останавливается (`{"waiting": {"prompt": …}}`), человек отвечает в терминале, и программа запускается заново со всеми ответами (время, случайности и ответы сети в пределах сеанса те же; запись в хранилище — только при настоящем завершении).

Дополнительно: `vx_translate(text, len, lang) → 1/0` — перевод `.vlhmn` (§11), `vx_set_llm(model)` — модель сервера ИИ для ключа кэша, импорт `env.vx_host_llm(json) → u64` — диалог серверу ИИ; `vx_run_ast(json, len, maxSteps) → 1/0` — проверить (как в §11) и исполнить готовый AST, в результате есть поле `vlstd`; `vx_format(src, len, from, to) → 1/0` — текст на другом языке или `{ok:false, diagnostics}`.

Экспорты: `vx_alloc(len)`, `vx_free(ptr, len)`, `vx_run(src, len, lang, maxSteps) → 1/0`, `vx_parse(src, len, lang) → 1/0`, `vx_result_ptr()`, `vx_result_len()`, `vx_set_input(ptr, len)`, `vx_set_time(ms: f64)`, `vx_set_permissions(bits)` (бит 0 — файлы, бит 1 — сеть), `vx_set_keywords(ptr, len) → 1/0`, `vx_version()`, `vx_reset_host()`. `lang`: 0 — ru, 1 — it, 2 — scn; `maxSteps = 0` — 3 000 000.

Результат `vx_run`: `{"ok", "stdout": [...], "warnings": ["строка:колонка  КОД  текст"], "diagnostics": [{"code","message","line","col","len","hint"?}]}`.

Импорты `env.*`: `vx_host_read(p,l)`, `vx_host_write(pp,pl,dp,dl)`, `vx_host_delete(p,l)`, `vx_host_list()`, `vx_host_get(p,l)` → `u64 = (ptr << 32) | len` на буфер `"ok\n…"`/`"err\n…"`, выделенный через `vx_alloc`; ядро освобождает его. `vx_host_ask(kind) → u32` (1 — файлы, 2 — сеть; 1 = разрешено).

## 11. `.vlhmn` — программа свободным текстом

`.vlhmn` равноправен `.vlstd`: LLM переводит текст в тот же нейтральный AST, а исполняет его то же ядро.

```text
Сделай список покупок: хлеб, молоко и сыр.
Потом выведи каждый пункт с тире в начале.
```

даёт ровно AST первых строк `examples/ru/04-loops.vlstd` (проверяется тестом).

**Конвейер** (`crates/vladx-hmn`, сети в нём нет — провайдер подключается снаружи):

1. Файл режется на прозу и блоки кода в тройных кавычках ```` ``` ````. Блоки кода разбирает обычный парсер, в LLM они не уходят — так форматы смешиваются в одном файле. Имена, объявленные выше по файлу, передаются модели как контекст.
2. Для каждого куска прозы модель получает системный промпт, собранный из данных проекта: зарезервированные слова — из `keywords.toml`, справка по AST и stdlib, примеры — пары `crates/vladx-hmn/fewshot/*.vlhmn` + `*.vlstd` (AST строит настоящий парсер). Ответ — один JSON: `{"confidence": 0..1, "questions": [...], "program": Program}`.
3. **Проверка** (`vladx_syntax::validate`): схема (типы serde) → печать AST в `.vlstd` → разбор этого текста → деревья обязаны совпасть → статические проверки. Ошибка — **один** повтор с перечнем проблем; вторая ошибка — `E-HMN-003`.
4. Уверенность ниже порога (по умолчанию **0.8**, `--min-confidence`, `VLADX_MIN_CONFIDENCE`) — программа не запускается (`E-HMN-004`), человеку показываются перевод и вопросы ИИ.
5. Кэш по SHA-256 от (версия промпта, модель, язык, контекст, текст): повторный запуск не тратит запросов (`.vladx-cache/hmn/` рядом с файлом).

Исполняется проверенный AST; ошибки исполнения указывают на строки показанного перевода.

**Где ключ.** Ключ Polza.ai и модель хранятся на сервере, клиент присылает только диалог перевода. Протокол сервера ИИ один для всех:

- `GET` → `{"available": bool, "model": "...", "reason"?}` (ключ не раскрывается);
- `POST {"messages": [{"role", "content"}, ...]}` → `{"ok": true, "content": "<ответ модели>", "model"}` или `{"ok": false, "error"}`.

Его реализуют `deploy/shared/vladx-llm.php` (shared-хостинг: модель и лимиты в `config.php`, только диалоги перевода VladX, лимиты по IP и в сутки, проверка Origin, необязательный токен) и `vladx serve` (`/llm` и любой `…/vladx-llm.php`). Промпт, проверку ответа, повтор и кэш делает ядро у клиента:

- **браузер** — WASM-экспорт `vx_translate`; запрос к модели идёт через импорт `vx_host_llm`, а worker пересылает его синхронным XHR на `vladx-llm.php` рядом со страницей (или на адрес из поля «ИИ»);
- **CLI** — `VLADX_LLM_PROXY=https://сайт/vladx-llm.php` (+ `VLADX_LLM_PROXY_TOKEN`), ключ на компьютере не нужен. Без посредника CLI может ходить в Polza напрямую: ключ `POLZA_API_KEY` (или `POLZA`, `VLADX_LLM_KEY`), модель `VLADX_LLM_MODEL` (по умолчанию `anthropic/claude-haiku-5.5` — дешёвая модель для разбора, §15.1 ТЗ).

**Оценка** (критерий фазы 5: ≥ 90 % фраз → корректная программа, не больше одного повтора): `vladx hmn-eval spec/hmn-eval/ru` — для каждой фразы `NN.vlhmn` сравнивает вывод программы с `NN.out` (ввод для `спроси` — `NN.in`).

## 12. Форматирование и перевод между языками

`vladx fmt файл [--to it] [--write]` печатает AST обратно в канонический текст. Комментарии и пустые строки сохраняются, `иначе { если … }` и `иначе если` остаются как были написаны. С `--to` ключевые слова переводятся на другой язык; имена не меняются. Если в языке нет нужного слова (у `scn` нет «больше или равно»), это ошибка `E-FMT-001`, а не порча программы. После печати текст разбирается заново, и AST обязан совпасть с исходным. На площадке то же делает «перевести на…» (`vx_format`).

## 13. Открытые вопросы (не решать за автора)

1. Слова `it` и `scn` — проверка носителем (`status = "draft"`); у `scn` нет форм для `≥`, `≤` и имён типов.
2. Интерполяция `{имя}` против `+` — сейчас `{имя}`, выражения внутри запрещены.
3. Предупреждения вместо ошибок в приведении типов — подтвердить.
4. Орфографическая норма сицилийского.
5. `пройди по` — отдельная конструкция или алиас `для каждого`.
6. Порог уверенности LLM для `.vlhmn` — сейчас 0.8 и настраивается; что считать «низкой уверенностью», решает автор.
7. Сообщения диагностики пока только на русском (слова языка программы подставляются из словаря).

## 14. Решения, принятые при реализации (там, где ТЗ было неоднозначно)

- `будет` — служебное слово объявления (`[op.support.be]`), а не форма `var.declare`. В `it`/`scn` (и как альтернатива в `ru`) после имени пишется `=`.
- Латинский литерал `null` не включён в `ru`: правило «никаких английских ключевых слов» сильнее.
- Слово «то» после условия необязательно; `иначе если` разрешено без лишних скобок.
- Роль служебного слова `для каждого … из` называется `iter` (нейтральный id).
- Пойманная ошибка исполнения — отдельный тип значения с полями `код`/`сообщение`; брошенное через `брось` значение ловится как есть.
- В строках, вложенных в список/словарь, печать ставит кавычки: `["а", "б"]`; на верхнем уровне строка печатается как есть.
- Нейтральная форма AST (сравнение трёх языков) не включает `value` у строк с интерполяцией: там исходный текст со словами языка (`{это.имя}` / `{questo.имя}`), а смысл целиком в `parts`.
- Каноническое итальянское «для каждого … из» — `per ogni … in` (как в примере ТЗ); `di` остаётся синонимом.
