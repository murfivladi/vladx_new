## 0. Главное в семи строках

1. **VladX** — интерпретируемый язык, где код читается как фраза на живом языке.
2. Ключевые слова — **только** на русском (`ru`), итальянском (`it`) и сицилийском (`scn`). **Английских ключевых слов нет.**
3. Один и тот же код на трёх языках даёт **байт-в-байт одинаковый нейтральный AST**.
4. Ядро — **Rust**, компилируется в **WebAssembly**; в браузере работает всё, включая **настоящие файлы и сеть** — без JS-движка и без второго интерпретатора.
5. Слова ключевых слов живут в **одном файле данных** (`keywords.toml`), а не в коде парсера.
6. Ошибка обязана **учить**: где, что не так, что написать вместо. Код ошибки — латиницей и стабильный.
7. Есть второе, равноправное представление программы — `.vlhmn`: свободный текст, который LLM переводит в тот же AST.

## 2. Словарь ключевых слов (полный, как в коде)

**Правило №1 проекта: слова живут только в `spec/keywords.toml`.** В исходниках парсера нет ни одной словоформы — парсер читает словарь и работает с каноническими `id` операций.

```toml
default_lang = "ru"
```

### 2.1 Как добавить операцию (обязательный порядок)

1. Добавить `[[op]]` в `spec/keywords.toml` (id + слова на трёх языках).
2. `cargo run -p xtask` — проверка словаря (дубли словоформ, пустые операции).
3. Ключ в `crates/vladx-syntax/src/keywords.rs`, разбор в `parser.rs`.
4. Исполнение в `crates/vladx-runtime/src/lib.rs`.
5. Тест в `crates/vladx-runtime/tests/exec.rs` и пример в `examples/` (он же проверяется скриптом).

## 3. Лексика и синтаксис `.vlstd`

### 3.1 Основные правила

- Исходник — UTF-8; BOM допускается и игнорируется; нормализация NFC.
- Ключевые слова сравниваются **без учёта регистра** (`Скажи` = `скажи`).
- Отступы **не значимы**: блоки задаются `{ }`.
- **Порядок слов фиксирован.** Парсер не пытается «понять» перестановку — он даёт `E-ORDER-001` и показывает канонический вариант.
- Две инструкции в одной строке без `;` — ошибка `E-SYNTAX-016` (с подсказкой «перенесите на новую строку»).
- Идентификатор: буквы текущего языка проекта, цифры, `_`; не может совпадать с ключевым словом (`E-IDENT-002`).
- Строки — только в кавычках. Интерполяция — `{имя}`; литеральная скобка — `\{`.
  Внутри `{…}` допускается **только имя или путь по полям** (`{человек.имя}`). Выражение там — ошибка `E-STRING-003` с подсказкой «вынесите в переменную». Это сделано намеренно: строка не должна становиться вторым парсером.
- Число — float64. `5` печатается как `5`, а не `5.0`.

### 3.2 Грамматика (EBNF, канон `ru`; для `it`/`scn` слова подставляются, структура та же)

```ebnf
программа   := инструкция*
инструкция  := объявление | присваивание | вывод | ввод
             | условие | цикл | функция | возврат
             | прерывание | продолжение | попытка | импорт | выражение

блок        := "{" инструкция* "}"

(* объявления *)
объявление  := "пусть" имя "будет" выражение
переменная  := "изменяй" имя "станет" выражение
присваивание:= цель "станет" выражение
цель        := имя ("." имя)*

(* ввод-вывод *)
вывод       := "скажи" выражение
ввод        := "спроси" выражение "и сохрани в" имя

(* управление *)
условие     := "если" выражение "то" блок ("иначе" блок)?
цикл        := "пока" выражение блок
             | "повторяй" выражение "раз" блок
             | "для каждого" имя "из" выражение блок
прерывание  := "прерви"
продолжение := "продолжи"

(* функции *)
функция     := "функция" имя "(" параметры? ")" блок
параметр    := имя (":" имяТипа)? ("=" выражение)?
возврат     := "верни" выражение?

(* ошибки *)
попытка     := "попробуй" блок "поймай" имя блок
бросить     := "брось" выражение

(* модули *)
импорт      := "импортируй" имя | "из" строка "возьми" списокИмён

(* выражения, по возрастанию приоритета *)
выражение   := или
или         := и ("или" и)*
и           := сравнение ("и" сравнение)*
сравнение   := сумма (("больше"|"меньше"|"равно"|"не равно"
                      |"больше или равно"|"меньше или равно") сумма)?
сумма       := произведение (("+"|"-") произведение)*
произведение:= унарное (("*"|"/"|"%") унарное)*
унарное     := ("-"|"не") унарное | постфикс
постфикс    := первичное (("(" аргументы? ")") | "." имя)*
аргумент    := (имя "=")? выражение        (* позиционные и именованные *)
первичное   := число | строка | список | словарь | "ничего" | "истина" | "ложь"
             | "это" | имя | "(" выражение ")"
             | "функция" "(" параметры? ")" блок              (* лямбда *)
             | "создай объект с прототипом" выражение блок
список      := "[" (выражение ("," выражение)*)? "]"
словарь     := "{" (ключ ":" выражение ("," ключ ":" выражение)*)? "}"
ключ        := имя | строка
```

### 3.3 Язык `it` — как читается тот же код

```text
sia nome = "mondo"
dì "ciao, {nome}"

funzione somma(a, b) {
  rendi a + b
}

se somma(2, 3) maggiore 4 allora {
  dì "funziona"
} altrimenti {
  dì "no"
}

per ogni cosa in ["pane", "latte"] {
  dì "- {cosa}"
}
```

### 3.4 Язык `scn`

```text
fussi nomu = "munnu"
dici "ciao, {nomu}"
```

Сицилийский пока минимален (три операции задействованы: `fussi`, `dici`, `pi ogni`); орфографическая норма **не утверждена** — это блокер, см. §14.

## 4. Семантика

### 4.1 Значения

`Null` · `Bool` · `Number` (f64) · `Str` · `List` · `Map` · `Function` (замыкание) · `NativeFn` · `Module` · `Object` (с прототипом).

### 4.2 Изменяемость

- `пусть` — неизменяемая привязка. Повторное объявление того же имени в блоке → `E-NAME-001`.
- Присвоение неизменяемой → `E-NAME-002` («объявлено через «пусть» и не может меняться»).
- `изменяй` создаёт изменяемую привязку; переприсвоение — слово `станет`.
- Содержимое списков и словарей изменяемо всегда — это не меняет привязку.

### 4.3 Приведение типов (реализуется 1:1, проверяется тестами)

| Выражение | Результат | Предупреждение |
|---|---|---|
| `"5" + 3` | `"53"` | `W-COERCE-001` |
| `5 + "3"` | `"53"` | `W-COERCE-001` |
| `"5" * 2` | `10` | `W-COERCE-002` |
| `ничего + 1` | `1` | `W-COERCE-003` |
| `истина + 1` | `2` | — |
| `ничего == ничего` | `истина` | — |
| `0 == "0"` | `истина` | `W-COERCE-004` |

Правило: операция выполняется, но в консоль печатается предупреждение. Предупреждения (`W-*`) не останавливают программу.

### 4.4 Скоуп, функции, прототипы

- Блочный скоуп; `если`, `пока`, `функция` создают новый скоуп.
- Функции — первого класса, замыкания захватывают по ссылке; рекурсия разрешена, глубина ограничена (`E-LIMIT-002`).
- Аргументы позиционные и именованные (именованные — после позиционных); значения по умолчанию вычисляются при каждом вызове.
- Нет `верни` → возвращается `ничего`.
- Лишние/недостающие аргументы → `E-ARGS-001` / `E-ARGS-002` до исполнения тела.
- Прототипы: `создай объект с прототипом <выражение> { поля }`; поиск свойства идёт по цепочке; `это` — текущий объект; чтение свойства у `ничего` → `E-NULL-001`.

### 4.5 Ошибки

1. Исключения: `попробуй { } поймай ошибку { }`, `брось значение`. Необработанное → `E-UNCAUGHT`, программа завершается.
2. Ошибки-значения: там, где сбой ожидаем (файлы, сеть, JSON), функция возвращает ошибку с кодом.

### 4.6 Лимиты исполнения (обязательны с первого дня)

| Лимит | По умолчанию | Код при превышении |
|---|---|---|
| шаги | 10 000 000 (в браузере 3 000 000) | `E-LIMIT-001` |
| глубина рекурсии | 1 000 | `E-LIMIT-002` |
| секунды | 10 (в CLI) | мягкая остановка |

Лимит шагов — это то, что спасает демо от `пока истина { }`.

## 5. Нейтральный AST (контракт между всеми частями)

**Один смысл — один AST.** Один и тот же код на `ru`, `it`, `scn` должен давать идентичный JSON (позиции `span` при сравнении отбрасываются). Это проверяется тестом, а не обещанием.

Формат: JSON, `draft 2020-12`, `schema_version = 1`, полная схема — `spec/ast.schema.json` (36 определений).

Корень:

```json
{ "kind": "Program", "schema_version": 1, "lang": "ru", "body": [ ... ] }
```

Узлы инструкций (поле `kind` — дискриминатор): `Declare` (name, mutable, value), `Assign` (target, value), `Say` (value), `Ask` (prompt, name), `If` (test, then, else), `While`, `Repeat` (times, body), `ForEach` (item, iter, body), `Break`, `Continue`, `FunctionDecl` (name, params, body), `Return`, `Try` (body, error_name, handler), `Throw`, `Import` (module | path + names), `ExprStmt`.

Узлы выражений: `NumberLit`, `StringLit` (value + parts), `BoolLit`, `NullLit`, `ListLit`, `MapLit`, `Identifier`, `Binary` (op, left, right), `Unary`, `Call` (callee, args), `Member` (object, property), `SelfExpr`, `FunctionExpr` (params, body), `ObjectExpr` (proto, entries).

`StringPart` = `{kind:"Text", value}` | `{kind:"Hole", expr}`. `Entry` = `{key, value}`. `Arg` = `{value, name?}`. `Param` = `{name, typeHint?, default?}`. `Block` = `{kind:"Block", body, kind?}`.

Реальный пример (`vladx parse`):

```vladx
пусть имя будет "мир"
скажи "привет, {имя}"
```

```json
{
  "kind": "Program",
```

## 6. Стандартная библиотека (всё уже работает в браузере и в CLI)

Модули — значения в глобальном скоупе: `numeri.корень(16)`. Имена человеческие; короткие алиасы (`длина`, `размер`) вынесены в глобальные функции.

|---|---|

| `liste` | `добавь`, `размер`, `возьми`, `сортировка`, `переверни`, `содержит`, `найди`, `кусок`, `соедини`, `выбери` |
| `mappe` | `ключи`, `значения`, `есть`, `размер`, `удали` |
| `caso` | `дробь`, `целое`, `выбери`, `перемешай` |
| `tempo` | `сейчас`, `миллисекунды`, `часы` |
| `json` | `запиши`, `прочитай` |
| `file` | `прочитай`, `запиши`, `есть`, `список`, `удали` |
| `rete` | `получи`, `получиJson`, `разрешено` |

Глобальные: `скажи` (= `выведи`), `длина`, `размер`, `строка`, `число`.

Поведение, которое нужно повторить точно:

- `liste.кусок(список, от, до)` — правая граница **не включается**; `testo.кусок(строка, от, до)` — индексы **в символах**, не в байтах.
- `liste.выбери(список)` — случайный элемент; `caso.выбери` — то же для списка, `caso.перемешай` — копия в случайном порядке.
- `tempo.сейчас()` — часы:минуты:секунды из текущего времени хоста; `tempo.миллисекунды` — мс; `tempo.часы(3661)` → `01:01:01`.
- `json.запиши(значение)` → компактная строка; `json.прочитай(строка)` → значения языка. Ошибка разбора → `E-JSON-001`.
- `file.список()` возвращает **относительные пути** (вложенные — как `папка/файл.txt`), отсортированные.
- `file.запиши("папка/файл.txt", …)` создаёт папки сам.
- `rete.получи(url)` → тело ответа строкой; `rete.получиJson(url)` → значение; `rete.разрешено()` → `истина/ложь`.

**Правило развития:** API сначала пишется на самом VladX, нативные примитивы в Rust — только там, где нужен доступ к платформе (файлы, сеть, время, случайности).

## 8. WebAssembly: ABI и правила

Сборка: `cargo build -p vladx-wasm --target wasm32-unknown-unknown --release`, без `wasm-bindgen` (только C-ABI, чтобы файл был один и грузился «как есть»).

`.cargo/config.toml`:

```toml
[build]
target-dir = "/home/user/.cache/vx/target"      # вне репозитория и вне /tmp (там мало места)

[target.wasm32-unknown-unknown]
rustflags = ["-C", "link-arg=--allow-undefined"]  # импорты vx_host_* даёт JS, а не линкер
```

Экспорты:

| Функция | Смысл |
|---|---|
| `vx_alloc(len) -> *mut u8`, `vx_free(ptr, len)` | буферы для строк UTF-8 |
| `vx_run(srcPtr, srcLen, lang, maxSteps) -> u32` | полный цикл: разбор + статика + исполнение; результат в буфере |
| `vx_parse(srcPtr, srcLen, lang) -> u32` | только AST в JSON |
| `vx_result_ptr() -> *const u8`, `vx_result_len() -> usize` | где лежит результат |
| `vx_set_input(ptr, len)` | ответы для `спроси`, по одному на строку |
| `vx_set_time(ms: f64)` | текущее время хоста (в WASM своих часов нет) |
| `vx_set_permissions(bits)` | бит 0 — файлы, бит 1 — сеть |
| `vx_set_keywords(ptr, len)`, `vx_version() -> u32` | подмена словаря на лету, версия схемы AST |

`lang`: `0` — ru, `1` — it, `2` — scn.

JSON-результат `vx_run`:

```json
{ "ok": true, "stdout": ["…"], "warnings": ["…"], "diagnostics": [] }
```

при ошибке:

```json
{ "ok": false, "stdout": ["частичный вывод"],
  "diagnostics": [{"code":"E-NAME-002","message":"…","line":3,"col":1,"len":12,"hint":"…"}] }
```

Импорты (5, все `env.*`): `vx_host_read`, `vx_host_write`, `vx_host_delete`, `vx_host_list`, `vx_host_get`. Каждая принимает указатель+длину (кроме `list`) и возвращает `u64`, упакованный как `(ptr << 32) | len` на буфер вида `"ok\n…"` или `"err\n…"`; ядро читает буфер и освобождает его через `vx_free`.

## 9. Браузер: настоящие файлы и сеть (самое сложное место проекта)

> **Важно понимать разницу платформ.** Node.js ничего не блокирует: его модель
> прав включается флагом `--permission`, а `--allow-net` появился только в Node 25.
> Всё «ультра-изолированное» в этом разделе — это **браузер**: он не даёт странице
> с `file://` ни worker'а, ни своего хранилища, а CORS запрещает читать чужие сайты.
> На диске (CLI) ничего этого нет: там доступно всё и без флагов.

### 9.1 Требование

В браузере должно работать **всё**, включая чтение/запись файлов и настоящие HTTP-запросы, **без второго движка и без JS-реализации языка**. Ядро — единственный интерпретатор.

### 9.2 Почему для этого нужен worker (проверено в настоящем Chromium)

| Проверка | `file://` | `http://` |
|---|---|---|
| WebAssembly | да | да |
| `new Worker(blobURL)` | **нет** | да |
| OPFS (`navigator.storage.getDirectory`) | **нет** | да |
| синхронный OPFS (`createSyncAccessHandle`) в worker | — | **да** |
| синхронный XHR в worker | — | **да** (в том числе к чужому домену с CORS) |

Следствие: **страницу нужно отдавать по http** (`vladx serve`), а ядро исполнять в worker'е. Интерпретатор синхронный по своей природе (он спрашивает и ждёт), а worker — единственное место, где браузер разрешает ждать.

### 9.3 Как устроен worker (это надо воспроизвести)

1. Страница создаёт worker из Blob с исходником, передаёт base64-WASM один раз (`boot`).
2. На `run`: `vx_reset_host()` → `vx_set_time(Date.now())` → `vx_set_input(...)` → `vx_set_permissions(bits)` → `await prepare()` → **синхронный** `vx_run` → `postMessage({type:'result'})` → `await finalizeStore()`.
3. Импорты `vx_host_*` внутри worker'а обслуживаются **там же**: чтение файла, запись в буфер, список, HTTP.

### 9.4 Ловушки OPFS, на которые уже наступили (не повторять)

- `createSyncAccessHandle()` возвращает **промис** — вызывать его из синхронного импорта нельзя. Ручки открываются **до** запуска (`prepare()`), читаются синхронно во время запуска, закрываются сразу после (`release()`).
- Создать **новый** файл синхронно нельзя вообще. Поэтому `file.запиши` кладёт данные в буфер записи (`Map имя → содержимое`); программа сразу видит свои файлы, а worker раскладывает буфер по настоящим файлам в `finalizeStore()` сразу после запуска.
- `removeEntry` асинхронный → удаления тоже копятся в буфере.
- Список файлов держится в служебном индексном файле `.__vladx_index` (по имени на строку), потому что обход хранилища асинхронный, а `file.список()` синхронный.
- Если ручку не закрыть, файл нельзя перезаписать или удалить — «h.close is not a function» и «NoModificationAllowedError» здесь типичные симптомы.

### 9.5 Сеть в браузере

- `rete.получи(url)` → синхронный `XMLHttpRequest` в worker'е.
- Напрямую работает, если сайт отдаёт CORS (проверено на `api.github.com`).
- Если CORS нет — страница показывает понятную ошибку и предлагает прокси. Прокси — тот же `vladx serve`: `GET /fetch?url=…` тянет адрес с сервера и отдаёт с `Access-Control-Allow-Origin: *`. Поле «прокси» рядом с галочкой «сеть» (по умолчанию `http://localhost:8000`).
- Адрес обязан начинаться с `http://` или `https://` (иначе `E-NET-001`).

### 9.6 Разрешения: по умолчанию всё открыто

Модель — как в Node без флагов: **никаких предварительных разрешений не нужно**.
Галочки «файлы» и «сеть» в площадке включены; в CLI доступно всё.

Если человек снял галочку, а программа всё равно просит доступ:

1. ядро не молчит и не падает — оно вызывает `vx_host_ask(kind)`;
2. worker сообщает странице `{type:'ask', kind}` (блокирующе ждать нельзя:
   `SharedArrayBuffer` в обычной странице недоступен, `Atomics.wait` не работает);
3. страница **после** вывода программы рисует ненавязчивую панель:
   «Программа просит доступ: файлы в хранилище страницы. [Разрешить и запустить] [Не сейчас]»;
4. по «Разрешить» ставится галочка и **программа запускается заново**; по «Не сейчас» —
   статус «доступ отклонён», сообщение остаётся `E-FILE-001`/`E-NET-001`
   с текстом «нужно разрешение человека на доступ к …».

Блокирующих `window.confirm` нет намеренно: диалог из worker'а не показать, а
панель в выводе работает везде и не мешает автозапуску программы.

### 9.7 Состав площадки (`site/playground.html`, один файл, ≈1 МБ)

Редактор с нумерацией строк, вывод, чипы примеров (11 на `ru`, 2 на `it`, 1 на `scn`), переключатель языка, кнопка AST, панель ввода для `спроси`, галочки разрешений, поле прокси, панель файлов хранилища (открыть/сохранить/скачать). WASM встроен как `const WASM_B64 = "…"`, сборка — `scripts/build-site.sh` (собрать → base64 → подставить в HTML).

Если WebAssembly недоступен (например, iframe с CSP без `'wasm-unsafe-eval'`), страница **не подменяет ядро заглушкой**, а объясняет причину и что сделать. JS-фолбэка нет и быть не должно — это осознанное решение автора языка.

## 10. CLI

```
vladx — интерпретатор VladX (v0.1)

Использование:
  vladx run <файл> [--lang ru|it|scn] [--no-net] [--restrict-files]   выполнить программу
  vladx parse <файл> [--lang ru|it|scn] [--keywords <путь>]   печать AST в JSON
  vladx check <файл> [--lang ru|it|scn]                       только диагностика
  vladx keywords [--lang ru|it|scn]                           словарь форм
  vladx serve [--port 8000]                                   площадка и прокси

  по умолчанию открыто всё (как в Node): любые файлы и сеть;
  сузить: --no-files, --no-net, --restrict-files (только папка программы)
```

- **Умолчания как в Node:** открыто всё. Файлы — любой путь (относительные считаются от папки программы, абсолютные и `..` работают), сеть — без флагов. Сузить можно флагами `--no-files`, `--no-net`, `--restrict-files`.
- **Файлы в CLI** — настоящий диск через `std::fs`; `file.список()` рекурсивный, служебные папки (`target`, `.git`, `node_modules`) не показываются.
- **Сеть в CLI** — настоящий HTTPS через `ureq` + rustls, таймаут 20 с, `User-Agent: vladx/0.1`.
- **Словарь вшит в бинарь** (`include_str!`), поэтому `vladx` работает из любой папки; `--keywords` позволяет подменить.
- `vladx serve` — статический сервер проекта + `GET /fetch?url=…`. Одна причина существования: браузер не даёт worker и OPFS на `file://`, а прокси нужен для сайтов без CORS. Слушает `0.0.0.0`, печатает адреса при старте.

## 12. Тесты и критерии приёмки

### 12.1 Что должно быть зелёным


Тесты проверяют **утверждения из спеки**, а не «не упало»:

- `пусть` нельзя менять (`E-NAME-002`);

- таблица приведения типов §4.3 — по одному тесту на строку;
- файлы и сеть: без разрешения — отказ, с разрешением — данные, запись доходит до хоста, удаление доходит до хоста, ошибка хоста доходит до программы;

- **просьба вместо отказа**: при снятой галочке человека спрашивают ровно один раз, и при согласии программа продолжает работу.

```vladx
скажи "язык: {ответ.language}"

пусть начало будет testo.кусок(страница, 0, 45)
```

### 13.13 JSON, списки, строки, случайности, время

```vladx
пусть человек будет { имя: "Аня", город: "Палермо", теги: ["язык", "код"] }
скажи json.запиши(человек)

пусть назад будет json.прочитай(json.запиши(человек))
скажи "имя: {назад.имя}"

пусть числа будет [5, 2, 9, 1]
скажи liste.сортировка(числа)
скажи liste.кусок(числа, 1, 3)
скажи numeri.округли(3.7)
скажи caso.перемешай(числа)
скажи tempo.часы(3661)
```

Вывод этой программы (зафиксирован при проверке документа):

```text
{"имя":"Аня","город":"Палермо","теги":["язык","код"]}
имя: Аня
[1, 2, 5, 9]
[2, 9]
4
[2, 5, 9, 1]
01:01:01
```

Обратите внимание на две вещи, на которых спотыкаются новички (и модели):

- модуль называется **`liste`**, а не `lista`; `lista.содержит(...)` — ошибка `E-NAME-004`;
- `{выражение}` внутри строки **запрещено** (`E-STRING-003`): сначала `пусть д будет …`, потом `{д}`.

## 17. Правила, которые нельзя нарушать (свод)

1. **Никаких английских ключевых слов.** Только `ru`/`it`/`scn`.
2. **Слова — данные, не код.** Ни одной словоформы в парсере.
3. **Один смысл — один AST.** Тест эквивалентности трёх языков обязателен.
4. **Порядок слов фиксирован**, парсер не «догадывается».
5. **Единственный движок — Rust/WASM.** Ни JS-фолбэка, ни второго интерпретатора — даже если WASM запрещён политикой страницы (тогда честное сообщение об ошибке).
6. **По умолчанию открыто всё** (решение автора 19.11.2026): файлы и сеть работают без флагов, как в Node. Ограничения — `--no-files`, `--no-net`, `--restrict-files` и снятые галочки в площадке; в этом случае доступ либо спрашивается у человека, либо отказ объясняется кодом.
7. **Ошибка учит:** позиция + код + текст + подсказка. Код латиницей, стабильный.
8. **Лимиты исполнения с первого дня.**
9. **Тесты с первого дня**, и они проверяют утверждения спеки.
10. **Не добавлять «страховочные» подсистемы**, о которых не просили. Сначала спросить.
11. **Deliverables — файлы** в рабочей папке проекта; главный артефакт — спецификация.

| `id` операции | латинский идентификатор в `keywords.toml` (`ctrl.foreach`), к нему привязаны словоформы |
| `пусть` / `изменяй` / `станет` | неизменяемое объявление / изменяемое объявление / переприсвоение |
| `это` | self внутри метода объекта |
| Host | трейт из 5 операций (`read/write/delete/list/get`) — единственный канал во внешний мир |
| разрешения | по умолчанию всё открыто; биты 1 — файлы, 2 — сеть позволяют сузить доступ, тогда ядро либо спрашивает человека, либо отказывает с кодом |
| OPFS | постоянное хранилище браузера; файлы живут между запусками |
| прокси | `GET /fetch?url=…` у `vladx serve` — обход отсутствия CORS |
