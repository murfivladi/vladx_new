# VladX на shared-хостинге

Площадка VladX целиком работает в браузере: ядро — WebAssembly, интерфейс — IDE. Хостинг с PHP
делает её максимально похожей на Node.js:

| Как в Node | Кто это делает |
|---|---|
| вывод появляется по ходу выполнения, как `console.log` | ядро в браузере |
| `спроси` останавливает программу и ждёт ответа в терминале | `index.php` включает изоляцию страницы (COOP/COEP) |
| файлы пишутся сразу, в момент `file.запиши`, и живут на сервере | `vladx-fs.php` |
| `rete.получи` читает любые сайты — ограничений CORS нет | `vladx-fetch.php` |
| время идёт (`tempo.сейчас`, `tempo.миллисекунды`) | ядро в браузере |
| `.vlhmn` — программа обычным текстом, ключ ИИ только на сервере | `vladx-llm.php` |
| пакеты, как npm: `vladpm publish`, `vladpm add`, панель «Пакеты» в IDE | `vladpm-registry.php` + сайт `vladpm.html` |

## Что загрузить

Готовый архив `vladx-shared.zip` есть в каждом релизе
(<https://github.com/murfivladi/vladx_new/releases/tag/nightly>):

| Файл | Зачем |
|---|---|
| `index.php` | отдаёт площадку с заголовками изоляции страницы |
| `playground.html` | площадка: IDE, примеры, ядро VladX внутри |
| `vladx-fs.php` | файлы программ на сервере: у каждого браузера своя рабочая папка |
| `vladx-fetch.php` | сеть программ через сервер |
| `vladx-llm.php` | ИИ для `.vlhmn`: добавляет ключ и модель Polza.ai |
| `vladpm-registry.php` | реестр пакетов vladpm: регистрация, публикация, поиск |
| `vladpm.html` | сайт реестра: поиск, карточки пакетов, README, версии |
| `vladx-common.php` | общее: настройки, лимиты, проверки |
| `config.example.php` | образец настроек |
| `.htaccess` | закрывает настройки и данные (Apache) |

## Установка

1. Загрузите файлы в папку сайта, например `public_html/vladx/`.
2. Создайте настройки из образца. Надёжнее — уровнем выше папки сайта, в `vladx-config.php`
   (туда веб-сервер файлы не отдаёт); можно и рядом, в `config.php`:

   ```php
   <?php
   return [
       'polza_api_key' => 'ваш ключ с https://polza.ai/dashboard/api-keys',
       'model'         => 'anthropic/claude-haiku-5.5',
   ];
   ```

   Без ключа всё работает, кроме `.vlhmn`.
3. Откройте `https://ваш-сайт/vladx/`. В строке состояния должно быть «⚡ как Node»,
   а у раздела «Хранилище» — «· сервер».

Нужны PHP 7.2+ и расширение curl. Сайт должен открываться по `https://`. Рядом со скриптами
появится папка `vladx-data/` (файлы программ и счётчики лимитов) — у PHP должно быть право
на запись в папку сайта; `.htaccess` закрывает её от посторонних.

Проверка: `https://ваш-сайт/vladx/vladx-fs.php`, `…/vladx-fetch.php` и `…/vladx-llm.php`
должны ответить JSON с `"available": true` (ключ в ответе не показывается).

## Файлы программ

Каждый браузер получает свою рабочую папку на сервере (случайный ключ хранится в браузере,
на сервере — его хеш). Чтобы открыть те же файлы на другом устройстве, скопируйте ключ
в «Настройки → Файлы программ» и вставьте его там же на другом устройстве.

Пределы (в `config.php`): `fs_quota_bytes` — объём одной папки (10 МБ), `fs_max_files` —
число файлов (500), `fs_max_workspaces` — число папок на сервере (1000).

## Сеть

`vladx-fetch.php` читает сайт по просьбе программы и отдаёт ответ браузеру. Чтобы сервер
не стал «дверью» во внутреннюю сеть хостинга, запрещены адреса локальной и служебной сети
(в том числе после перенаправлений), ограничены размер ответа (`fetch_max_bytes`, 5 МБ),
время (20 с) и частота (`fetch_per_ip_per_hour`).

## Реестр пакетов vladpm

`vladpm-registry.php` — реестр, как registry.npmjs.org, только на файлах: пакеты, учётные записи и
токены лежат в `vladx-data/registry/` (пароли и токены — только хешами). Сайт реестра —
`https://ваш-сайт/vladx/vladpm.html`; площадка рядом сама находит реестр (панель «Пакеты»).

Реестр по умолчанию в `vladpm` — `https://vladinc.ru/vladx`. Свой реестр указывается так:

```bash
export VLADPM_REGISTRY=https://ваш-сайт/vladx
```

Читать (поиск, карточки, скачивание) может кто угодно и с любого сайта; публиковать — только
вошедший пользователь. Регистрация открыта; закрыть — `'registry_open_signup' => false`
в `config.php`. Пределы: `registry_max_package` (1 МБ), `registry_unpublish_hours` (72),
`registry_signup_per_hour`, `registry_login_per_hour`, `registry_publish_per_hour`.

Проверка: `https://ваш-сайт/vladx/vladpm-registry.php` отвечает `{"registry": "vladpm", …}`.

## ИИ и расходы

Модель меняется в `config.php` (`'model' => 'anthropic/claude-sonnet-5.5'` — точнее, но заметно
дороже). Перевод одного короткого текста на `claude-haiku-5.5` стоит порядка 0,1 ₽, повтор того же
текста берётся из кэша. Посредник сам выбирает модель и длину ответа, принимает только перевод
`.vlhmn` для VladX и ограничивает число запросов: `per_ip_per_hour` и `per_day`.

## Защита

- Страницы с чужих сайтов получают отказ (свой сайт разрешён всегда; другие — `allowed_origins`).
- Для CLI можно включить токен `access_token` (латиница и цифры) — `vladx` шлёт его из `VLADX_LLM_PROXY_TOKEN`.
- Имена файлов проверяются: нельзя выйти из рабочей папки (`..`) и создать скрытый файл.

## CLI с тем же сервером

```bash
export VLADX_LLM_PROXY=https://ваш-сайт/vladx/vladx-llm.php
```

```bash
vladx run examples/ru/14-shopping.vlhmn
```

CLI и так работает как Node: файлы — на вашем диске, сеть — напрямую.

## Без хостинга

`vladx serve` отдаёт ту же площадку локально и отвечает по тем же адресам `vladx-*.php`;
файлы программ пишутся прямо на диск, в папку `--files` (по умолчанию `vladx-files/`).
